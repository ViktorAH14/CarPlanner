# CarPlanner

> Приложение для учёта расходов на автомобиль: заправки, ТО, ремонты, средний расход топлива и напоминания о техобслуживании.

## 🚀 О проекте

CarPlanner помогает пользователям отслеживать затраты на заправки, рассчитывать средний расход топлива, вести учёт любых трат по машине и не пропускать сроки технического обслуживания благодаря умным напоминаниям.

Приложение поддерживает синхронизацию данных между всеми устройствами пользователя и работает в офлайн‑режиме: все изменения сохраняются локально и отправляются на сервер при появлении интернета.

**Стек технологий:**

- **Фронтенд:** Flutter (Android, Windows, Linux)
- **Бэкенд:** Node.js + Express + Sequelize
- **База данных:** PostgreSQL
- **Управление состоянием:** Riverpod (запланировано на следующую итерацию)
- **Контейнеризация:** Docker & Docker Compose

## 📱 Особенности фронтенда (текущее состояние)

Фронтенд реализует чистую архитектуру на основе фич (feature‑based) с интерфейсом в стиле Material 3 и полным покрытием тестами главного дашборда.

**Ключевые возможности**

- **Главный экран** (lib/features/home/presentation/home_screen.dart): отображает заголовок, три карточки статистики («Топливо», «Сервис», «Ремонт и прочее») и кнопку «Добавить запись».
- **Адаптивная вёрстка:** используется SingleChildScrollView для корректного отображения на экранах разных размеров.
- **Дизайн Material 3:** применяется ThemeData(useMaterial3: true) с базовым цветом‑семенем для единого визуального стиля.
- **Виджет‑тесты:** включены подробные тесты в test/home_screen_test.dart, проверяющие отрисовку UI и взаимодействие (например, отображение SnackBar при нажатии кнопки).
- **Документация:** все публичные классы и методы содержат комментарии в формате DartDocs (///), совместимые с генерацией документации через dart doc.

**Как сгенерировать документацию фронтенда**
Из директории frontend/ выполните:

```bash
dart doc --open
```

Это создаст HTML‑документацию в папке CarPlanner/frontend/doc/api и откроет её в браузере.

## 💻 Настройка для разработчика (Бэкенд)

Бэкенд полностью упакован в контейнеры. Не нужно устанавливать Node.js или PostgreSQL локально.

### 1. Настройка переменных окружения

Скопируйте шаблон и задайте свои значения:

```bash
cp .env.example .env
```

Необходимые переменные в `.env`:

| Переменная          | Описание                                   |
| ------------------- | ------------------------------------------ |
| `POSTGRES_USER`     | Имя пользователя PostgreSQL                |
| `POSTGRES_PASSWORD` | Пароль пользователя PostgreSQL             |
| `POSTGRES_DB`       | Имя основной базы данных (`carplanner_db`) |
| `JWT_SECRET`        | Секретный ключ для подписи JWT‑токенов     |

Docker Compose автоматически формирует `DATABASE_URL` и `TEST_DATABASE_URL` на основе этих значений. Не добавляйте строки подключения к БД в `.env`.

### 2. Запуск всего стека (Backend + БД)

```bash
docker compose up
```

Сервер будет работать на порту **3000**. Отладчик Node.js доступен на порту **9229**.

При первом запуске Postgres создаст базы `carplanner_db` и `carplanner_test_db` с помощью скрипта в `docker/postgres/`.

### 3. Запуск тестов бэкенда

Тесты используют изолированную базу данных (`carplanner_test_db`). Строки подключения берутся из Docker Compose; скрипт тестов устанавливает только `NODE_ENV=test` и фиксированный `JWT_SECRET` для проверки middleware.

```bash
docker compose run --rm backend npm run test
```

Перед каждым запуском тестовый набор удаляет и заново создаёт все таблицы (`sequelize.sync({ force: true })`).

### Автоперезагрузка

В контейнере включён `nodemon`. Сохранение файлов в `backend/src` автоматически перезапускает сервер.

## 📡 Документация API (Текущий статус)

Модуль аутентификации полностью реализован и протестирован. При входе возвращается подписанный JWT‑токен. Защищённые маршруты требуют валидный заголовок `Authorization: Bearer <token>`.

### Публичные эндпоинты

| Метод | Эндпоинт             | Описание                        | Успех       | Ошибки                                             |
| ----- | -------------------- | ------------------------------- | ----------- | -------------------------------------------------- |
| POST  | `/api/auth/register` | Регистрация нового пользователя | 201 Created | 400 (отсутствуют поля), 409 (email уже занят)      |
| POST  | `/api/auth/login`    | Аутентификация пользователя     | 200 OK      | 401 (неверные учётные данные), 400 (пустой запрос) |

**Ответ при входе** содержит JWT‑токен:

```json
{
  "data": {
    "user": { "id": 1, "email": "user@example.com" },
    "token": "eyJhbGciOiJIUzI1NiIs..."
  }
}
```

### Защищённые эндпоинты

| Метод | Эндпоинт                 | Описание                                | Успех  | Ошибки                                      |
| ----- | ------------------------ | --------------------------------------- | ------ | ------------------------------------------- |
| GET   | `/api/protected/profile` | Получение данных пользователя по токену | 200 OK | 401 (отсутствует/невалидный/истёкший токен) |
| POST  | `/api/protected/data`    | Пример аутентифицированной записи       | 200 OK | 401 (отсутствует/невалидный/истёкший токен) |
